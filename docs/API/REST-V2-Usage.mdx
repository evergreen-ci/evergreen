# REST v2 API

To use Evergreen's REST v2 API, all URLs start with a path of `/rest/v2`. For more information on authentication, please see [our authentication documentation](./Authentication).

## General Functionality

Please see [A note on authentication](REST-V1-Usage#a-note-on-authentication) for authentication instructions.

### Errors

When an error is encountered during a request, the API returns a JSON
object with the HTTP status code and a message describing the error of
the form:

```
{
 "status": <http_status_code>,
 "error": <error message>
}
```

### Pagination

API Routes that fetch many objects return them in a JSON array and
support paging through subsets of the total result set. When there are
additional results for the query, access to them is populated in a [Link
HTTP header](https://www.w3.org/wiki/LinkHeader). This header has the
form:

```
"Link" : <http://<EVERGREEN_HOST>/rest/v2/path/to/resource?start_at=<pagination_key>&limit=<objects_per_page>; rel="next"

<http://<EVERGREEN_HOST>/rest/v2/path/to/resource?start_at=<pagination_key>&limit=<objects_per_page>; rel="prev"
```

To fetch all results, follow the `rel="next"` link verbatim until no Link
header is returned, rather than constructing pagination URLs yourself.
Every paginated endpoint documents its pagination style in the OpenAPI
spec via an `x-pagination-type` operation extension:

| Pagination type         | Meaning of the pagination key                                                   | Endpoints                                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `time-cursor`           | `start_at` is a timestamp (RFC3339); pages list results at or before that time  | `/admin/events`, `/projects/{project_id}/events`, `/projects/{project_id}/patches`, `/users/{user_id}/patches` |
| `task-id-cursor`        | `start_at` is the identifier of the last task on the previous page              | `/builds/{build_id}/tasks`, `/projects/{project_id}/revisions/{commit_hash}/tasks`                             |
| `host-id-cursor`        | `start_at` is the identifier of the last host on the previous page              | `/hosts`, `/users/{user_id}/hosts`                                                                             |
| `project-id-cursor`     | `start_at` is the identifier of the last project on the previous page           | `/projects`                                                                                                    |
| `revision-order-cursor` | `start` is a version revision order number; pages list older versions           | `/projects/{project_id}/versions`                                                                              |
| `page-number`           | `start_at` is a zero-based page number; each page holds up to `limit` results   | `/tasks/{task_id}/tests`                                                                                       |
| `stats-cursor`          | `start_at` is a compound cursor over statistics, as returned by the Link header | `/projects/{project_id}/task_stats`, `/projects/{project_id}/task_reliability`                                 |
| `log-time-cursor`       | `start` is a timestamp (RFC3339); links appear only when `paginate=true`        | `/tasks/{task_id}/build/TaskLogs`, `/tasks/{task_id}/build/TestLogs/{path}`                                    |

Unless stated otherwise, the default page size is 100.

### Dates

Date fields are returned and accepted in ISO-8601 UTC extended format.
They contain 3 fractional seconds with a 'dot' separator.

### Empty Fields

A returned object will always contain its complete list of fields. Any
field that does not have an associated value will be filled with JSON's
null value.

## OpenAPI specification

Evergreen publishes an **OpenAPI 3.0** specification for the REST v2 API,
generated from the API's source code:

[https://mciuploads.s3.amazonaws.com/evergreen/latest/swagger.json](https://mciuploads.s3.amazonaws.com/evergreen/latest/swagger.json)

The file is named `swagger.json` for historical reasons, but its contents are
OpenAPI 3.0. It is regenerated and republished when changes are merged to
Evergreen's main branch, so it tracks the latest merged code and may be slightly
ahead of what is currently deployed.

You can use it to generate a client in your language of choice, rather than
writing REST calls by hand. For example, with
[openapi-generator](https://openapi-generator.tech/):

```bash
curl -O https://mciuploads.s3.amazonaws.com/evergreen/latest/swagger.json
openapi-generator generate -i swagger.json -g python -o evergreen-client
```

The API docs below are rendered from this same specification.

### Notifications (DEPRECATED)

Create custom notifications for email or Slack issues.
